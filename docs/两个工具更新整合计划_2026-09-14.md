# 两个工具更新整合计划（2026-09-19，修订 3）

## 1. 目标与范围

本轮只规划同步“病历自动抽取”和“基金金额测算”的最新能力，不修改“文件批量编码”。整合方式继续遵守现有边界：上游项目负责业务核心，飞检工具包保留自己的标签页、独立 Worker、任务状态和打包入口；不把上游的独立 `Tk` 主窗口直接复制进标签页。

## 3. 功能变化与整合影响

### 3.1 病历自动抽取 V1.9

新增抽取方式“按科室基金支付总金额前十”，与原有“按年份随机抽取”并列：

- 日期范围内先按既有就诊键合并同一份病历，再按科室分组；
- 每个科室按基金支付总额降序选前 10 份，金额相同时保持源数据首次出现顺序；
- 支持数值和含千位分隔符的文本金额，空科室、无效金额和非有限金额不参加排名；
- 新方式要求“科室名称”和“基金支付总额”，不要求随机模式专用的医疗类别、住院号、目录名称和目录编码；
- 新方式不使用“每文件条数”和随机种子，结果参数页要明确记录“不适用”；
- 输出增加规范列“科室名称”和“基金支付总额”，继续排除人员编号和证件号码等敏感列，源文件保持只读。

对飞检工具包的影响：

1. `components/medical_record/extractor.py` 同步 V1.9 核心，不引入上游 `app.py`。
2. 病历标签页增加只读下拉框并持久化 `extraction_mode`；旧设置没有该字段时默认随机抽取，无效值回退到默认值。
3. 选择科室前十模式时禁用“每文件条数”和“随机种子”。标签页只在随机模式解析这两个输入，避免禁用框中的无关旧值阻止任务启动。
4. Worker 载荷增加 `extraction_mode`，并原样传给核心函数；进程隔离方式不变。
5. 上游当前仍在科室前十模式的输出文件名中带“种子”。首轮同步保持上游行为，避免整合包产生私有分叉；后续如需去掉，应先在上游统一修改并补测试。

### 3.2 基金金额测算 V1.0.0

V0.9.0 将结果区从八列扩展为九列，在“数量总和”后新增“人次”：

- 每条成功进入汇总的 Excel 明细计 1 人次，不按人员或就诊 ID 去重；
- 空白行、其他险种和异常行不计人次，隐藏或筛选隐藏的有效明细仍计数；
- 串换只改变数量，不改变人次；
- 各分组人次之和必须等于“计算成功数”；
- 汇总表范围由 `A:H` 扩展到 `A:I`，基金金额和报销比例右移到 `H:I`，审计区由 `I:J` 移到 `J:K`。

V0.9.1 在此基础上增加三项与文件安全直接相关的修复：

1. 在保存前读取 `.xlsx`/`.xlsm` ZIP 包中的公式缓存，`openpyxl` 保存后再恢复缓存，使同一含公式文件可以连续测算两次；公式本身继续保留。没有缓存值的公式仍明确失败，且不修改原文件。
2. 固定比例规则不使用动态门诊比例，因此不再要求输入表包含“基金支付总额”；通用和串换规则的要求不变。
3. 保存后不再从硬编码的 `D5` 取基金合计，而是按标签查找；同时校验九列表头、基金金额合计及人次合计，全部通过后才替换原文件并生成备份。

V0.9.1 阶段主要同步 `components/fund_calculator/fund_calculator.py`，标签页和 Worker 调用签名无需变化。新增的 `zipfile`、`posixpath` 和 `xml.etree.ElementTree` 都是 Python 标准库，不增加安装依赖。公式缓存恢复属于高风险文件写入路径，应按上游原样同步，不在整合时顺带重构 ZIP/XML 逻辑。

V1.0.0 新增“两项同时收取”：按就诊 ID 及所选时间口径配对两个项目，支持“同日同时同分、同日同时、同日、同一次住院”。因此基金标签页新增规则选项和同时口径，Worker 载荷新增 `simultaneous_scope`；旧载荷缺少该字段时默认“同日同时同分”。

## 4. 实施顺序

### 阶段 A：冻结上游版本

1. 锁定病历项目 `277355e`/V1.9。
2. 锁定基金项目 `7ad4a13`/V1.0.0，不以 V0.9.x 中间提交作为最终基线。
3. 两个上游项目都必须保持工作区干净且与 `origin/main` 一致；导入前分别复跑完整测试。

### 阶段 B：同步业务核心

1. 逐文件对比并同步两个 `components` 目录中的业务核心。
2. 不复制独立应用窗口、发布 EXE、构建目录、样例原件或上游设置代码。
3. 更新 `component-lock.json`：病历锁定 `277355e`/V1.9，基金锁定 `7ad4a13`/V1.0.0。
4. 单独提交每个组件的同步，便于按工具回退，不把两项业务变更混成一个不可拆分提交。

### 阶段 C：适配标签页与 Worker

1. 为病历标签页加入模式选择、模式持久化和参数启停逻辑。
2. 为病历 Worker 增加模式字段并验证默认模式兼容旧载荷。
3. 基金标签页增加“两项同时收取”和同时口径，Worker 兼容缺少新字段的旧载荷；日志不依赖结果 Sheet 的固定列号，并保留批量文件隔离和备份提示。
4. 不改变三个标签页的顺序、主窗口尺寸策略和组件独立进程边界。

### 阶段 D：回归与发布

1. 把上游新增的纯业务测试移植到飞检工具包，并保留源文件哈希、备份和异常隔离测试。
2. 增加病历标签页模式持久化及 Worker 载荷测试；基金至少覆盖九列输出、人次勾稽、隐藏行、固定比例缺少基金支付总额、带缓存公式连续运行两次、无缓存公式不改原文件。
3. 为基金补充一个脱敏 `.xlsm` 回归样例，验证公式缓存恢复后 ZIP 包完整、VBA 内容保留且 Excel 可以正常打开；若暂时没有可用样例，则将此项列为发布阻断项而不是跳过。
4. 运行飞检工具包全部单元测试、GUI 冒烟和 Worker 冒烟。
5. 用脱敏 Excel 做两项端到端验证：病历源文件哈希不变；基金原业务 Sheet 不变且测算前备份与原文件一致。
6. 重新构建 Windows 安装程序，执行静默安装、应用启动、Worker 和卸载冒烟，再生成 SHA-256。

## 5. 验收标准

- 病历标签页可在两种模式间切换；重启后恢复上次模式，旧设置文件继续可用。
- 科室前十结果按科室分别限制为最多 10 份，金额降序及并列顺序与上游测试一致。
- 随机抽取的既有结果、隐私过滤和可复现性不发生回归。
- 基金结果固定为九列；人次口径、列位置、格式和审计区位置与上游最终设计一致。
- 基金金额、数量、报销比例和原有两份脱敏样例金额不因新增人次发生变化。
- 含有效公式缓存的基金文件连续测算两次均成功，公式和缓存值均保留；无缓存公式失败时源文件字节不变。
- `.xlsm` 文件处理后仍保留 VBA 内容，生成的 Office ZIP 包结构完整并可由 Excel 正常打开。
- 固定比例输入可缺少“基金支付总额”，通用和串换输入仍按原规则校验该字段。
- “两项同时收取”可选择四种同时口径，整合页、Worker 与上游核心收到的口径一致。
- 保存后的表头、基金金额合计或人次合计任一不一致时，原文件不得被替换。
- 两个组件的文件影响策略不变：病历只新建结果，基金安全替换并保留测算前备份。
- 任一组件初始化或任务失败不影响另外两个标签页。
- `component-lock.json` 可追溯到两个干净、已推送且测试全绿的上游提交。
- 新安装包在未安装 Python 的 Windows x64 测试环境可完成安装、启动和卸载。

## 6. 暂不纳入本轮的事项

- 不更新文件批量编码组件。
- 不重构基金单文件架构，也不把三个组件合并到同一业务进程。
- 不改变病历科室前十的业务口径或输出命名；发现的命名问题先回到上游解决。
- 不复制两个上游项目中的独立发布 EXE；安装包只从飞检工具包自身构建。
